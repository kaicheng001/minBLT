## 3. Algorithmic contract

### 3.1 Raw bytes and conventions

- The fundamental data is a sequence of bytes, each with value 0 through 255.
- Use reversible UTF-8 conversion: `text.encode("utf-8")` and `bytes(...).decode("utf-8", errors="replace")` for human-readable display. Keep bytes as the source of truth because an arbitrary generated byte string may not be valid UTF-8.
- The predictive head has exactly 256 ordinary next-byte classes. Internal BOS, padding, or other sentinels may use IDs above 255, but must never be confused with ordinary bytes or silently emitted by the output head.
- Make input and target shifting explicit. State the exact convention in code comments and in the README.
- Work on single sequences and small batches. Handle padding without allowing it into the attention context or loss.

### 3.2 Two patching methods, with entropy patching as the centerpiece

Implement:

1. `FixedPatcher`: split at a fixed byte interval. This is a sanity baseline only.
2. `EntropyPatcher`: choose patch starts using causal estimates of **next-byte entropy** from a separate small byte LM.

For byte position `t`, given preceding bytes `x[:t]`, let a small autoregressive entropy model produce a probability distribution over the next byte. Define:

```text
H_t = -sum_v p(v | x[:t]) * log(p(v | x[:t]))
```

Implement at least the two paper-motivated boundary criteria:

```text
Global threshold:          start(t) if H_t > threshold
Relative / monotonicity:   start(t) if H_t - H_(t-1) > threshold
```

Always start the first patch at position 0. If the global threshold is enabled, support optional `max_patch_length` as a causal safety cap; this should never require looking at later bytes. Document edge cases and the difference between global and relative thresholds. Calibrate a GLOBAL threshold on a training/calibration split to reach an approximate desired average patch size if needed. A calibration pass may see the corpus, but once chosen, the threshold must stay fixed for online generation. Do **not** choose a top-k set of patch boundaries using the entire current sequence at generation time. That would break incrementality.

Provide a simple way to display something like:

```text
input:    Better than BPE!
patches:  [Bet] [ter ] [than] [ B] [PE!]
lengths:  [3, 4, 4, 2, 3]
```

The example above is illustrative only, not an expected output of the entropy model. Actual boundaries must come from actual model entropies. Include statistics for patch count and average bytes per patch.

Keep patch IDs, starts, and lengths unambiguous. Never allow empty patches, patches that overlap, or omitted bytes. Support bytes spanning arbitrary UTF-8 code-point boundaries because BLT patches bytes, not Unicode characters.

### 3.3 A real, separately trained entropy model

Implement `TinyEntropyModel` as a small autoregressive byte-level neural language model in `minblt/entropy.py`.

- It must predict a distribution over the next raw byte from prior bytes.
- A small causal Transformer using the same basic attention primitives as the BLT is preferred; it should be sufficiently tiny to train on CPU.
- Train it with next-byte cross-entropy, then freeze it for computing boundaries during BLT training and inference.
- Compute Shannon entropy from logits with numerically stable log-softmax and probabilities, using natural logarithms.
- The entropy computed for target position `t` must depend only on the prefix ending at `t - 1`.
- Avoid an external pretrained model, a random fake-entropy array, a deterministic hand-coded entropy heuristic, or a BPE tokenizer substituted for the entropy model.
- Provide a simple calibration helper for average patch size; report the achieved average, not only the target value.

Explain clearly: BLT's entropy-based segmentation is dynamic and data-driven, but the separate entropy model can be pretrained and frozen. Do not falsely describe the chosen hard patch boundaries as differentiable or jointly learned end-to-end with the large BLT model.

### 3.4 The BLT architecture: three genuinely interacting parts

Implement a small, functional `ByteLatentTransformer(nn.Module)` with three modules:

**A. Local Encoder**

- Input: raw byte embeddings, optionally including left-context byte n-gram hash embeddings.
- Apply one or two lightweight causal byte-level Transformer layers. Allow a configurable local/sliding attention window; it may cross patch boundaries, but it may not see future bytes.
- Create one latent representation for each variable-length patch.
- Use cross-attention pooling with patch queries and byte states as keys/values, restricted by patch membership. Initialize the query with a simple pooling operation over the patch's byte states, then apply learned projections and attention. Do not replace this with a flat reshape or an arbitrary fixed-stride pooling layer.
- Support different encoder and global dimensions using a clearly labeled learned projection.
- Return byte-level states and patch-level states with documented shapes.

**B. Global Latent Transformer**

- Input: patch representations, not the raw byte sequence.
- Apply a larger, causal Transformer over the sequence of patch embeddings.
- The global module must be where the expensive model capacity resides and must actually influence byte predictions and receive gradients.
- It should process fewer positions than the local byte modules whenever patches have average length greater than one.
- Use ordinary PyTorch causal attention with correct padding and position handling.

**C. Local Decoder**

- Predict the next individual byte using a small causal byte-level Transformer.
- Use a learned cross-attention mechanism that passes causally available global patch states into byte-level states. Queries come from byte states; keys/values come from global patch states.
- Restrict decoder cross-attention to the correct past patch context. You may use a short history window of completed patch states if it simplifies a meaningful attention operation.
- Produce `[batch, byte_time, 256]` logits.
- Keep the encoder, global transformer, and decoder separate and readable, rather than hiding everything in a single opaque routine.

Use reasonably faithful Transformer basics (e.g., RMSNorm, rotary or simple explained positional embeddings, a causal multi-head attention block, and a standard feed-forward or SwiGLU block). Favor readability over implementing every large-scale optimization. If a published feature is omitted, say so explicitly rather than silently replacing it.

### 3.5 Hash n-gram embeddings

BLT augments byte embeddings with information about preceding byte n-grams. Include a small, self-contained **optional** rolling hash n-gram embedding implementation, with one or a few configurable n-gram lengths. It must hash only the current and previous bytes, not look ahead. Use a fixed-size embedding table, modulo reduction, and clear comments about hash collisions.

The complete paper explores multiple n-gram lengths; a tiny default may use fewer lengths to remain CPU-friendly. Document this scale reduction and make it easy to turn the feature off in tests. Never introduce an actual BPE learned vocabulary or conflate patch IDs with token IDs.

### 3.6 CRITICAL: no future-byte leakage

This is the most important correctness requirement. A visually plausible encoder/patch/decoder diagram is NOT sufficient.

Implement a fully causal teacher-forced training computation. For the target byte at position `t`:

- The predicted distribution may depend on bytes `x[:t]` only.
- The patch-start decision at `t` may depend on `x[:t]` through the frozen entropy model, not on `x[t]` or any future byte.
- The decoder must not consume an unshifted local-encoder representation containing `x[t]`.
- The decoder must not consume a global representation built using the *current unfinished patch* or a future patch.
- If the encoder pools all bytes in patch `j`, that representation becomes available to predict subsequent patches only **after that patch's bytes have been observed**.
- At the very beginning, use an explicitly learned or fixed initial global context, not future content.
- When pooling and unpooling, patch IDs, offsets, and attention masks must follow exactly the same causal convention during training and generation.

A safe conceptual approach is:

1. Build causal encoder byte states for the observed byte sequence.
2. Pool a completed patch `j` to a latent state and process it with the causal global transformer.
3. For byte positions belonging to patch `j+1`, use only global states derived from patches up to `j` (and a causal shifted byte-level stream).
4. Predict each byte in the new patch autoregressively.

You may implement another valid shifted convention if it matches the paper more closely, but explain the indexing and PROVE it with tests. Pay special attention to the first byte, the first patch, patch transitions, final partial patches, padding, and cross-attention masks. Do not hide off-by-one errors behind `detach()` or `torch.no_grad()`.

### 3.7 Training and generation must agree

Implement:

```python
logits, loss = model(byte_batch, patcher=patcher)
output_bytes = model.generate(prompt_bytes, patcher=patcher, max_new_bytes=...)
```

You may refine the API if needed, but maintain a tiny public interface.

Generation must actually sample byte by byte. At each new byte position:

- Evaluate the causal entropy predictor using only the generated prefix.
- Decide whether a new patch starts, using the same frozen patching rule and threshold as in training.
- Run the BLT with strictly available context.
- Sample the next raw byte from its 256-way distribution (with optional temperature and top-k).
- Append it to the prefix and repeat.

A naive implementation that recomputes all the encoder/global/decoder states after each new byte is acceptable in this educational repository. KV caching is NOT required. Do not fake generation by looking at the continuation in the training data.

If using a placeholder position to obtain the next-byte logits in an uncached implementation, ensure the placeholder value cannot affect those logits. Add a regression test where different placeholder values yield identical next-byte logits.

### 3.8 Objective and metrics

Use standard next-byte negative log likelihood. Include a short, correct bits-per-byte calculation:

```text
BPB = total_next_byte_negative_log_likelihood / (num_predicted_bytes * ln(2))
```

Normalize by the number of valid predicted bytes, not the number of patches. Print training loss, optional validation BPB, number of patches, and average patch size. Label all reported metrics as tiny-model educational measurements, not paper-reproduction claims.

## 5. Required correctness tests

Use `pytest`. Make tests deterministic, small, and runnable on CPU. At minimum:

1. UTF-8 text-to-byte conversion works and raw bytes round-trip exactly, including non-ASCII input.
2. Fixed patching returns correct boundaries for short sequences, one-byte sequences, and trailing partial patches.
3. Entropy threshold tests with explicitly supplied toy entropy values produce the expected starts for global and relative methods.
4. Patch lengths are positive and sum exactly to the number of bytes. No overlap or omission is possible.
5. Prefix consistency: dynamic patch starts for a sequence prefix equal those obtained by processing the same prefix online, without knowing any continuation.
6. Causal entropy alignment: changing suffix bytes cannot change next-byte entropy estimates for earlier target positions.
7. BLT output shape is `[B, T, 256]` and its loss is finite for small batches with variable patch counts.
8. **Causal logits test:** keep the same byte prefix, modify an arbitrary future suffix, and verify all logits for the unchanged prefix are identical within numerical tolerance in `eval()` mode. Test changes that also alter future patch boundaries.
9. **Cross-patch leakage test:** specifically mutate a future byte *inside the same patch* and verify logits for earlier bytes in that patch are unchanged.
10. Initial patch and single-patch sequences work correctly and do not accidentally read their own complete pooled representation for prediction.
11. Encoder/global/decoder parameters all receive finite gradients on a sample containing multiple patches; verify global gradients are actually nonzero.
12. For a fixed model/patcher, a teacher-forced last-position logit equals the recomputed next-byte logit from the same prefix. If generation uses a dummy placeholder, test dummy-value invariance.
13. Saving and reloading a small trained or randomly initialized checkpoint preserves logits in eval mode.
14. CPU generation produces exactly the requested number of raw bytes, with each output in `0..255`, and does not depend on a network request.
15. `BPB` uses valid byte count, ignores padding, and matches its mathematical definition.

Test the hard indexing cases carefully: `T=1`, first byte, second byte, patch boundary positions, long one-patch span, multiple patches, non-ASCII UTF-8, and variable batch patch counts. A model that merely passes shape tests is not sufficient.

## 6. Implementation priorities and engineering judgment

Follow this order:

**Step 1.** Inspect reference repositories and paper. Write a short internal implementation plan, especially the exact next-byte indexing and completed-patch convention.

**Step 2.** Implement byte handling and deterministic fixed/entropy patch utilities. Unit-test boundaries and streaming consistency first.

**Step 3.** Implement and train the tiny entropy LM. Verify entropy and target-index shifting mathematically, then enable entropy-based patching.

**Step 4.** Implement minimal shared causal Transformer blocks, the local encoder and masked patch cross-attention, followed by the global transformer.

**Step 5.** Implement the local decoder, correct causal global-state shifting, and byte-level loss. Test suffix-mutation invariance before writing training scripts.

**Step 6.** Implement a small end-to-end training loop, checkpointing, `generate()`, and `demo.py`.

**Step 7.** Write the minimal README and tests. Run and fix all tests. Then run a genuine tiny train-and-generate smoke test using CPU.

Prefer the simplest implementation that is **correct**, not the shortest implementation that happens to run. Small Python loops over patches are fine; opaque batch-scattering tricks are not. Use `torch.nn.functional.scaled_dot_product_attention` only if mask semantics are understood and CPU-compatible; otherwise use explicit attention with documented masks. Guard against all-masked attention rows producing NaNs. Be precise about whether a Boolean mask means allow or disallow, as PyTorch APIs differ.

Use a small educational default (for example, encoder/decoder widths around 32–64, global width around 64–128, one to two local layers, and two global layers). Make the final choices based on achieving a quick CPU smoke test. Give the global transformer more capacity than either local block. Expose only a small number of meaningful hyperparameters; no giant config class.

Avoid:

- Importing the official `bytelatent` package.
- Copying official BLT attention or patcher implementations wholesale.
- Replacing entropy patching with regex, spaces, BPE merges, or random thresholds alone.
